## 무엇을 배웠나

1. **소형 모델에 안전 판단을 맡기면 안 됩니다.** ② 단독 모드는 "출하 승인 처리해줘" 같은 요청을 한 번도 거절하지 못했습니다(거절 0%). 승인·종결 요청과 업무 범위 밖 질문은 모델에 묻기 전에 규칙으로 막고(③), AI에게는 데이터를 바꾸는 도구를 아예 주지 않았습니다.
2. **도구 선택도 맡기지 않는 편이 낫습니다.** ②는 필요한 조회를 44%만 했고, 절차 질문에 문서를 찾지 않은 채 "조사가 열려 있지 않다면 재시험을 바로 해도 된다"처럼 절차와 반대되는 답을 지어냈습니다. 질문에 나온 로트와 절차를 시스템이 먼저 조회해 넘기자(③) 도구 선택 100%, 사실 포함 83%가 됐습니다.
3. **출처는 시스템이 붙입니다.** 3B 모델은 내용은 대체로 맞게 쓰지만 출처를 빼먹거나 받은 적 없는 문서 번호를 붙였습니다(③ 출처 64%, 근거 59%). 답을 문장별로 실제 조회 결과와 대조해 출처를 붙이고 가짜 출처는 지우자(④) 출처 96%, 근거 검사 100%가 됐습니다.
4. **근거 검사가 잡지 못하는 것도 있습니다.** 근거 검사는 "그 숫자·출처가 실제로 조회된 것인가"를 봅니다. 조회된 문서를 엉뚱한 질문에 갖다 붙이는 경우(예: OOS 로트에 설비 센서 교정 절차, mix-02)는 통과합니다. 그래서 정답을 정해 둔 평가 세트가 함께 필요합니다.
5. **임베딩 하이브리드 검색은 기본값으로 쓰지 않았습니다.** 검색 단계만 보면 bge-m3를 섞은 쪽이 조금 낫습니다(아래 표). 하지만 최종 답변 통과율은 76% → 68%로, 34문항 중 3문항 차이였고 바뀐 문항은 문서 순서가 달라져 모델이 다르게 쓴 경우였습니다. 이 규모에서는 이득을 확인할 수 없고, 모델 하나를 더 띄우는 비용이 들어 BM25를 기본으로 두고 임베딩은 설정으로 켤 수 있게 했습니다.
6. **응답 길이 상한이 필요합니다.** 모델이 같은 문장을 반복하다 300초를 넘긴 문항이 있었습니다. `max_tokens`를 두자 같은 문항이 정상적으로 답했습니다.
7. **규칙 기반(①)이 3B 모델보다 높게 나왔습니다.** 정해진 질문 유형에서는 규칙이 더 정확하고 빠릅니다. LLM의 이점은 영어 질문(① 67% → ④ 100%)과 문장으로 정리된 답에서 나타났습니다. 복합 질문(로트 상태 + 대응 절차)은 모든 방식이 0%로, 가장 먼저 개선할 부분입니다. GPU에서 7B 이상 모델로 같은 평가를 다시 돌려 비교하는 것이 다음 단계입니다.
